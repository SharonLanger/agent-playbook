## Preserve experiments and behavior

The user requires that no experiment be lost during test reorganization. Inventory experiment definitions, authored cases, scenarios, and relevant tests before and after the change. Moving a test must preserve its coverage. Do not delete any tests, including apparently redundant tests, as part of satisfying these review requirements. Flag deleted tests as findings; replacing or consolidating them needs a separate explicit decision. Flag any experiment deletion; do not treat a replacement test as permission to delete the experiment itself.

For every removed, superseded, or deferred test or experiment-derived check, trace its behavior to the replacement test scenario or scenarios. One old experiment/check may map to several scenarios. Match inputs, behavior, and meaningful assertions; similar names or a larger total test count are not proof of preservation. Identify anything unmapped, still deferred, skipped, or no longer collected. Deferred cases are not passing coverage.

Use PR 45's cleanup and deferred-test inventory as supporting context when needed to identify the scenarios PR 46 is intended to replace. Keep findings about PR 46 distinct from pre-existing gaps. The PR description says broader experiment-case migration is deferred; verify and report the remaining gaps against the user's coverage requirement rather than accepting that scope reduction as approval.

## Assert behavior directly rather than through files

Inspect the reorganized suite, remaining active tests, and shared helpers for file copying/writing followed by assertions on filenames, file existence, or reading generated files as the result assertion. Scenario assertions must check returned values, observable harness behavior, or in-memory captures directly, rather than experiment exports, reports, or historical result files.

Report every such file-based result assertion with its path, test name, what is written or read, what is asserted, and a suggested direct behavioral assertion. Follow helper calls and subprocess outputs; a test body alone may hide filesystem use.

The user clarified the testing boundary after review-01:
- Reading authored fixtures, including JSON input and expected data, and checking that JSON is parsed correctly is allowed.
- Ordinary behavior scenarios should assert returned behavior and in-memory events rather than write reports or logs and read them back to determine success.
- Keep existing dedicated file-persistence tests until replacements exist. Their isolated temporary-file writes and readbacks are permitted; do not delete, disable, weaken, or relabel them merely to satisfy a no-file rule.
- Defer redesign of the file-persistence layer to the planned SQLite work. This does not approve skipping its existing coverage or require implementing SQLite in PR 46.
- Classify fixture preparation, storage-contract checks, and checks for unwanted file changes separately from ordinary file-based output assertions. Do not remove useful immutability checks or input preparation based only on the presence of a filesystem operation.

This clarification resolves the earlier blanket conflict over existing dedicated persistence tests. It does not approve the whole feature design, reduce the required scenario coverage, or authorize edits during review.
