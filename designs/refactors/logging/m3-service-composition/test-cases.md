# Logging M3 revised acceptance cases

Status: proposed checks for the 2026-11-21 command contract. Runtime tests and M3 live acceptance **NOT RUN**. Previous MC cases and reports remain historical under `reviews/`. Each ID below is stable for the revised implementation.

| ID | Meaningful assertion and evidence |
|---|---|
| SC-01 CLI contract | Parser accepts exactly one `--start/--status/--stop` for `services` and `logs`; `--help`/invalid combinations invoke no Docker or loader. Existing `langfuse` actions, `--env-file`, `--check` disabled exit 3, direct pre-bootstrap script and installed-release rejection retain their contracts. Test in `app/tests/tooling/test_cli_tasks.py`, `test_development.py` and existing Langfuse management tests. |
| SC-02 selection | Real loader fixture exercises four logging/Langfuse enabled combinations, explicit relative `--config`, relative `AGENT_PLAYBOOK_CONFIG` and source default across the development subprocess cwd boundary, plus conflicting base/local/secrets-file/process override values. Assert aggregate start calls exactly enabled components in logs-then-Langfuse order; neither enabled exits 0 with no Docker. Invalid YAML/boolean/secrets selection exits 2 before any Docker start. |
| SC-03 explicit disabled logging | With `integrations.logging.enabled: false`, `logs --start` starts the existing logging project and does not write YAML/local/secrets files. `services --start` skips logs. Test both commands using the same fixture and byte comparison; repeat under process override. |
| SC-04 key independence | `logs --start/status/stop` and aggregate logs-only selection succeed without Langfuse project or infrastructure keys. With both enabled and project keys absent, aggregate service selection still reaches both local component managers; workflow `load_configuration` retains its existing key validation. No secret value appears in output. |
| SC-05 identity/persistence | Fake subprocess tests assert exact logging `--project-directory/-p/-f` and unchanged image, network, loopback binding, seven-day retention and volume target, including a conflicting ambient `COMPOSE_PROJECT_NAME` that cannot redirect logs. Langfuse resolves its effective project from the same selected Compose env and shell precedence used by the operation, then passes `-p` consistently; assert an env-file override, shell override, and collision with the reserved logging project. Repeated start creates no alternative project, and stop uses `down` without `-v`. Offline fixtures assert no volume delete/reset command. |
| SC-06 state/stop | Component status reports only its own project. Aggregate status reports both, including a disabled but running project; exit 0 when all enabled services are ready (also neither enabled), exit 1 if an enabled service is non-ready. Selection failure still reports physical states and exits 2. Aggregate stop invokes Langfuse then logs without loading application YAML, even after both are disabled; repeat stop exits 0 and leaves the sibling untouched for a component stop. If Langfuse's deployment `.env` is missing with candidate assets, status reports observed physical labels but readiness unknown and exit 2; stop refuses unsafe Langfuse teardown with restore guidance, still stops logs and returns 2. With no candidate assets, Langfuse stop succeeds and status is stopped. |
| SC-07 failures/deadlines | Simulate Docker unavailable, invalid Compose, occupied port, unhealthy service, HTTP timeout and Ctrl-C. Assert per-component 720-second monotonic cap includes engine, config, up, ps and HTTP; each call is clipped to remaining time. After an ordinary component failure, aggregate start still attempts the other enabled component, reports partial outcome and returns 1, or 2 if any configuration error. A coordinator Ctrl-C aborts before the next start with no implicit down; aggregate stop continues to logs after Langfuse failure and reports 1 or 2 by error class. Assert no spawn, state query, HTTP probe or sleep after the monotonic deadline, including on first-start asset inspection and with less than 5 seconds left for the logging connection check. Status/stop have 60-second caps. |
| SC-08 Langfuse safety/compatibility | Existing .env values and five named volumes remain byte/name-identical across aggregate operations. With selected `.env` missing, independently test each candidate container-only state and **each** of the five retained volumes alone (including custom project label/name), no candidate assets, failed container lookup and failed volume lookup. Assert any candidate asset or lookup failure blocks `setup.py` and `up`; a genuinely empty inventory initializes once. Present-file preflight targets the same Compose-resolved project as every operation, even when shell and file project names conflict. Custom `--env-file` passes unchanged and is required by the documented aggregate command. Existing `--logs/--follow/--open/--check` behavior and redaction remain covered. |
| SC-09 default test boundary | Maintained pytest uses fake Docker subprocesses and synthetic secrets, needs no daemon or Docker CLI, accesses no `app/examples/` path, and never reads user values. Optional, separately invoked `docker compose ... config --quiet` for each unchanged Compose file validates syntax; record CLI/Compose version or NOT RUN. Resolved config with real credentials is never printed. |
| SC-10 live Mac | In a real Mac session, record tested SHA, Docker/Compose versions and context; independently start/status/stop/restart **both** components, exercise the four aggregate enable combinations, stop one and confirm the other remains usable. Seed unique synthetic log-record and Langfuse-trace IDs, record exact query strings and observed matching fields before/after restart. Inspect the same physical volume IDs/names before/after and confirm no second project/empty replacement. Mark each unobserved step NOT RUN. Do not equate health with stored readback. |
| SC-11 workflow isolation | `run`/`dev-run` never call service management or require Docker. Application logging/tracing still follows YAML flags; explicit `logs --start` does not enable workflow logging. |
| SC-12 documentation and scope | `app/docs/cli.md`, configuration/logging/Langfuse guides, tooling README, index and Atlas link to shipped behavior and retained secret owners. Diff review confirms no project/volume rename, credential migration, provider/runner change, app/examples access or guarded contract edit. Mac `.txt` guide includes remaining M2 LG-10 failure/shutdown and exact correlation readback steps, marked NOT RUN until evidence exists. |

Map each SC ID to its appropriate evidence: maintained pytest node and assertion for offline behavior; exact command, version, tested SHA and observed result for opt-in Compose; environment/context, commands, IDs/queries and observed readback for live Mac; inspected paths/diff for documentation and scope. Do not invent pytest nodes for manual or review-only cases. Ordinary pytest, optional Compose config, live Mac and diff/doc review have separate PASS/FAIL/NOT RUN states. The design review verifies these proposed checks; it does not mark them executed.
