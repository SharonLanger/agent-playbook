# Logging M3 revised acceptance cases

Status: proposed checks for the 2026-11-21 command contract. Runtime tests and M3 live acceptance **NOT RUN**. Previous MC cases and reports remain historical under `reviews/`. Each ID below is stable for the revised implementation.

| ID | Meaningful assertion and evidence |
|---|---|
| SC-01 CLI contract | Parser accepts exactly one `--start/--status/--stop` for `services` and `logs`; `--help`/invalid combinations invoke no Docker or loader. Existing `langfuse` actions, `--env-file`, `--check` disabled exit 3, direct pre-bootstrap script and installed-release rejection retain their contracts. Test in `app/tests/tooling/test_cli_tasks.py`, `test_development.py` and existing Langfuse management tests. |
| SC-02 selection | Real loader fixture exercises four logging/Langfuse enabled combinations, local overlay and secrets-file/process overrides. Assert aggregate start calls exactly enabled components in logs-then-Langfuse order; neither enabled exits 0 with no Docker. Invalid YAML/boolean/secrets selection exits 2 before any Docker start. |
| SC-03 explicit disabled logging | With `integrations.logging.enabled: false`, `logs --start` starts the existing logging project and does not write YAML/local/secrets files. `services --start` skips logs. Test both commands using the same fixture and byte comparison; repeat under process override. |
| SC-04 key independence | `logs --start/status/stop` and aggregate logs-only selection succeed without Langfuse project or infrastructure keys. With both enabled and project keys absent, aggregate service selection still reaches both local component managers; workflow `load_configuration` retains its existing key validation. No secret value appears in output. |
| SC-05 identity/persistence | Fake subprocess tests assert exact logging `--project-directory/-p/-f` and unchanged image, network, loopback binding, seven-day retention and volume target. Langfuse uses its existing helper/project/`--env-file`. Repeated start creates no alternative project, and stop uses `down` without `-v`. Offline fixtures assert no volume delete/reset command. |
| SC-06 state/stop | Component status reports only its own project. Aggregate status reports both, including a disabled but running project; exit 0 when all enabled services are ready (also neither enabled), exit 1 if an enabled service is non-ready. Selection failure still reports physical states and exits 2. Aggregate stop invokes Langfuse then logs without loading YAML, even after both are disabled or files are missing; repeat stop exits 0 and leaves the sibling untouched for a component stop. |
| SC-07 failures/deadlines | Simulate Docker unavailable, invalid Compose, occupied port, unhealthy service, HTTP timeout and Ctrl-C. Assert per-component 720-second monotonic cap includes engine, config, up, ps and HTTP; each call is clipped to remaining time. Aggregate start still attempts the other enabled component, reports partial outcome and returns 1, or 2 if any configuration error. Status/stop have 60-second caps. |
| SC-08 Langfuse safety/compatibility | Existing .env values and five named volumes remain byte/name-identical across aggregate operations. Missing .env with any chosen-project container or volume fails before `setup.py` generates keys; fresh install still initializes once. Custom `--env-file` passes unchanged and is required by the documented aggregate command. Existing `--logs/--follow/--open/--check` behavior and redaction remain covered. |
| SC-09 default test boundary | Maintained pytest uses fake Docker subprocesses and synthetic secrets, needs no daemon or Docker CLI, accesses no `app/examples/` path, and never reads user values. Optional, separately invoked `docker compose ... config --quiet` for each unchanged Compose file validates syntax; record CLI/Compose version or NOT RUN. Resolved config with real credentials is never printed. |
| SC-10 live Mac | In a real Mac session, record Docker/Compose versions and context; run each component and aggregate combination, stop one and confirm the other remains usable, and query the same synthetic log record and Langfuse trace after restart. Inspect the same physical named volumes before/after; confirm no second project/empty replacement. Do not equate health with stored readback. |
| SC-11 workflow isolation | `run`/`dev-run` never call service management or require Docker. Application logging/tracing still follows YAML flags; explicit `logs --start` does not enable workflow logging. |
| SC-12 documentation and scope | `app/docs/cli.md`, configuration/logging/Langfuse guides, tooling README, index and Atlas link to shipped behavior and retained secret owners. Diff review confirms no project/volume rename, credential migration, provider/runner change, app/examples access or guarded contract edit. Mac `.txt` guide includes remaining M2 LG-10 failure/shutdown and exact correlation readback steps, marked NOT RUN until evidence exists. |
